## Architecture

A small locale module owns supported codes, translated interface strings, direction and font candidates. Shared HTML generation serves both deliverable and preview, with escaped user text and semantic links/figure. Renderers and config validation consume this module; PDF uses XeLaTeX with script-aware font/direction setup, DOCX uses script fonts and bidi paragraphs/runs. HTML becomes an explicit delivery platform/format and participates in immutable manifests and receipts, including mixed PDF/HTML exports.

DingTalk keeps official dws and adds explicit account/organization/profile binding to connection and publication. Inspect the current stable CLI/source; use real-account evidence to fix upload/import/readback contracts and preserve uncertain-write checkpoints. Upgrade only the task-scoped official binary after checksum verification.

Tencent preferred path is its **official MCP API** at https://docs.qq.com/openapi/mcp. The live official OAuth metadata at https://docs.qq.com/.well-known/oauth-authorization-server advertises public-client registration, device authorization and refresh tokens, with docs:read/docs:write/docs:manage scopes. Verify the device flow and request only read/write initially. This is an OAuth client, not a hosted OAuth backend. Store tokens in the OS credential store through a maintained keyring library; keep only non-secret references/account/location in course configs. Reuse preconfigured private environment references when supplied. Legacy application/COS API courses stay compatible. Discover actual tools/schemas before choosing upload/import/create and readback calls; missing capabilities or entitlements remain explicit blockers, never simulated account passes. Do not silently buy VIP or expand scopes.

The README uses an original centered identity, language navigation, compact release/license badges, user-facing v1/v2/version explanations near the top, real sample previews, clear feature cards and a short chat-first install/start flow. DeepTutor is a layout reference only; no copied branding, claims or prose. Technical validation, provider details and development belong in linked docs/optional details. Remove claims of support for unspecified other DOCX/Markdown platforms. Ten README versions link to each other and the same current release, with relative links valid from each location.
