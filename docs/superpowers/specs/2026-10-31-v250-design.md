# v2.5.0: learner-started review and course adjustment

Approved by the user before implementation. Continue inline and publish after validation.

When the learner returns, offer a small review queue grounded in actual answer events, feedback, hints and source references. Share the agreed daily time budget with new learning; balanced, new-first and review-only are explicit choices. Deferred review is not debt. Do not create review timers, reminders or assessment schedules. Heavy practical tasks remain opt-in.

Derive a transparent profile and on-demand weekly recap from recorded evidence. Delivery alone is not study. Silence, skipping and pending grading are unknown. Distinguish assisted answers from independent answers. A disputed judgment needs clarification, not an automatic weakness label. Keep self-reports separate, support exclusion/re-inclusion and deletion of private review data. Never infer a mastery percentage.

Review one frozen question in an isolated attempt, using existing lightweight answer/hint/skip/feedback controls. Preserve the original attempt and prevent normal quiz continuation from selecting a review attempt. Reference validation fails closed on changed source/course files.

Use a simple disclosed review heuristic: incorrect/partial now; assisted/revealed next day; independent correct after 3 days, increasing on subsequent independent review successes to a 30-day cap. This is not an optimal-memory model. No model service or new dependency is introduced.

Export explicit-request UTF-8 Anki CSV with Front, Back and Tags, literal text, source notes and stable version identity in the front field. Never export disputed, withdrawn or heavy questions as trusted cards. One-way export, no Anki result synchronization.

Store immutable proposed future config/plan revisions with current source hashes and actual assessment references or a user-request basis. Explicit acceptance creates a separate course archive awaiting normal plan rendering/inspection/approval. Preserve the old archive, historical records and schedules; never automatically approve, switch or reschedule. Copy necessary local assets and selected material snapshots safely.

Update all ten README version guides in user language, skill/reference instructions, metadata and release validation. Preserve all previous archives and unrelated research files.
