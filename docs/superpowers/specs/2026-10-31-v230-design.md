# v2.3.0: learner-started, lightweight checks

The user explicitly approved the conversation flow and authorized implementation, testing and remote publication. They explicitly excluded automatically scheduled quizzes and quiz reminders. No second design approval is needed. Baseline is v2.2.1 (`32e268d`); prior untracked research drafts are preserved.

## Experience and scope

When generating a daily lesson, prepare 1–3 questions aligned with its objectives and cited material, reserving practice time within the daily budget. Publish the ordinary document plus a short invitation to ask the agent for a check. Stop the delivery run normally. Start only when the learner requests it; no quiz timer, reminder or proactive new conversation is created.

Present one question at a time. Prefer a host-native choice/text card only when that host provides a suitable, readable response tool; otherwise use ordinary conversation. Do not label an answer recommended or treat preselection/silence as submission. Support single choice, brief text and open dialogue, hints, skipping, solution on request, pause/resume and explicit retake. Keep expected answers private until the learner submits or explicitly requests a solution. The owner can inspect their files; this is not a secure examination system.

Default questions require only selection, a few sentences or a brief exchange. No long writing, device operation, actual code authoring, experiment or project is assigned unless the learner explicitly requested a practice-dependent topic/training. Each question declares required actions. Heavy actions require a recorded original `practice_request`; this is a host attestation of the user's request, not an automatic consent detector. Content review must catch mislabeled heavy prompts. Reading/comparing supplied code is light; writing/running it is not.

## Runtime

Use standard-library modules; host authors questions and grades open responses. Store a private immutable quiz definition per lesson/revision and an atomic records file with append-only attempt events. Bind definitions to approved config/plan, reviewed manifest and lesson input hashes. Starting also requires verified delivery. Quiz state never alters course progress, receipts, approval hashes, schedule or the reserved mastery field. Completed courses may still be checked manually.

The schema includes estimated minutes, objective, prompt, response guidance, source IDs with exact lesson section/quote anchors, hints, action declarations, stable option IDs or grading criteria, expected answer and explanation. Validate scope references, unique IDs, light/default limits and effort consent. A quiz that exceeds the original practice allowance requires explicit extra-time consent at start. Preparing a changed definition requires a new revision; previous attempts remain bound to their original revision.

CLI: `quiz prepare/start/next/answer/hint/reveal/skip/pause/feedback/correct/status/export/forget`. Actions use stable request/event IDs; retries preserve events and conflicting reuse fails. Only public current-question fields are returned before an answer. Choice labels are presentation only; IDs determine correctness. Unicode labels and exact option text may be normalized without rewriting the raw answer. Open answers persist before model grading; grading must reference the latest answer event and cover all frozen rubric criteria with valid source IDs. Failed/stale grading never loses answers. Follow-up answers use explicit revision of a response and retain previous replies/feedback, marking assistance appropriately.

Feedback explains strengths, gaps, evidence and a small next step. Uncertain criteria yield `needs_review`, not an invented score. Corrections append history; a disputed choice-key result may be withdrawn or marked for review, not silently given a new key. New corrected keys require a new quiz revision. No overall mastery percentage or adaptive schedule is introduced.

## Data portability and privacy

Private files remain under course/learning with owner-only atomic writes and path guards. JSON export preserves quiz versions, all raw responses/events and known feedback; CSV is spreadsheet-safe and documents any formula escaping. Export does not send to cloud or another user. Forget requires an explicit confirmation flag and deletes only assessment data; existing course state/manifests/receipts survive. Export/forget remain available for broken historical delivery bindings so data can be recovered or removed.
