# Official API onboarding design

Approved conversational scope (2026-10-25): cloud destinations use official APIs, including official CLI wrappers; Obsidian is explicitly accepted as official CLI/local-Vault exception. UI import remains a user-chosen fallback, never equivalent to API acceptance. Aim for two or three normal onboarding dialogue rounds; exceptional permission/admin failures are explained separately.

Use the official `ntn` and `lark-cli` login/keychain/session management instead of inventing a token vault or OAuth backend. Existing direct-token API configurations remain supported. Add CLI publication transports with immutable existing receipt recovery. Notion reuses its existing Markdown/image API adapter through an authenticated CLI HTTP transport. Feishu uses official Word import and task-result shortcuts plus document/block and destination readback, always as user.

Add a connect helper that parses an ordinary page/folder URL, checks identity and destination using read-only official calls, and returns a secret-free delivery configuration. Named reusable connection profiles contain metadata only, outside course/repository. The current course snapshots the confirmed target/account; later profile/default changes cannot retarget an approved course. Missing binaries/auth/location return specific next actions and selected-provider guidance; the helper does not silently grant permissions or change routes. A successful connection check is not a write acceptance pass.

Agent handles installation, IDs, configuration, commands, and profile reuse. User supplies platform/location and performs necessary official authorization. No API keys or passwords in chat, code, subprocess arguments, logs or ZIP. Do not read/print CLI token exports. Request only needed document scopes, preserve provider confirmation gates. Auth status is separate from actual create/image/link/readback verification. Existing host/import courses are preserved; new courses default to API/official CLI.

Verification: red-green tests for transports, destination/identity binding, pending task reuse, malformed success, secret-free errors, URL parsing, profiles, and missing-auth guidance. Real accounts use isolated QA projects/parents, actual API creates/readback plus UI inspection. Never label fixtures or prior UI imports as API passes. Version 2.1.0 packages the onboarding workflow and adapters; historical tags/assets remain unchanged.
