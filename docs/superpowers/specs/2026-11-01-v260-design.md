# v2.6.0: dependable installation and first use

User approved the three-entry approach and requested full implementation, validation and publication. Preserve native Skill identity; do not publish a separate npm package. Use the existing skills CLI, native Codex/Claude Code installation and release ZIP/chat installation.

## Scope and choices

Reuse upstream installers rather than create a competing cross-agent npm installer. Add a small standard-library helper for bundle completeness/discovery evidence and safe ZIP install/update for hosts without a native updater. Alternative hand-copy-only instructions lack update safety; a custom npm service duplicates upstream tooling and adds maintenance without helping these flows.

Installation validation distinguishes complete files, expected host path and actual native inventory/invocation evidence. Files alone never prove native discovery. Do not crawl unrelated settings, access credentials, change global defaults or replace a user's active installation during QA. Test real installer commands in isolated destinations.

First use checks the selected route only. Standard-library HTML/Markdown needs no pip packages; DOCX/PDF/cloud routes return exact selected dependencies and official-tool steps. Reuse existing connections, guide only missing location/auth details and never infer authorization from a browser login. Successful access checks remain separate from write/readback acceptance.

Course archives and reusable connections live outside installed Skill roots. Refuse creating a course inside a recognizable Skill tree. ZIP upgrades require a managed installation receipt, matching installed bytes and a verified SHA256. Stage and validate the complete replacement first, retain an exact backup and refuse unknown/local changes, symlinks and path escapes. Native-manager installations use their own updater; never overwrite them blindly. No credentials or courses are migrated into a new Skill bundle.

Retain the existing public flat catalog fields and marketplace manifest. Add a proper Claude plugin manifest if actual validation requires it. Keep package and repo versions consistent at v2.6.0. Update English default plus nine README versions with install entry points, first-use expectations and update guidance.

## Acceptance

Real community CLI repository install/list/update and local pre-release install; official Codex installer into a test destination; official Claude plugin validate/install/list/update in isolated configuration where available. ZIP fresh install/upgrade/integrity refusal and source/package equivalence. Test first-use dependency and access recovery, connection reuse, and unchanged course/learning/connection data across updates. Preserve earlier ZIPs. No claim of native client UI/semantic invocation, cloud write acceptance or account authorization without actual evidence. Tag/release and download/verify remote assets; finish with concrete tested limitations if an upstream environment blocks a surface.
