# Omni Learning Anything v2.0.0 文档交付升级设计

日期：2026-10-14（Asia/Shanghai）  
状态：设计待用户确认；尚未修改实现或升级版本。  
基线：main / e82f3e8，当前 Skill 版本 1.0.1。

## 目标与范围

保留个性化学习、来源核验、计划批准、每日课程、定时执行、暂停和恢复机制，扩展学习计划和每日材料的输出与交付。v2.0.0 必须覆盖用户点名的 Notion、Obsidian、飞书、腾讯文档和钉钉，保留 PDF，并增加独立生成的 Markdown、DOCX。平台支持表区分原生文档直写、导入交付和需要用户操作的离线文件，不能把本地文件冒充已交付的云文档。

“市面上大部分主流软件”没有固定边界。本版以这五个平台为明确验收范围；其他支持 DOCX/Markdown 导入的平台提供通用文件路径，已有 Google Docs、Microsoft Word 等可写连接器时可通过宿主工具接入，但未实测的平台不宣称原生 API 支持。

原请求“如果用户每月明确声明”暂按“如果用户没有明确声明目标平台”理解。本设计不新增按月强制询问。

## 三种方案及取舍

1. 只提供 Markdown/DOCX 导入文件：实现简单、覆盖广，但每次学习需要手动上传，不满足持续云文档交付的主要目标。
2. 所有平台都要求 API 密钥：便于无人值守，但企业权限和授权门槛高；Obsidian 本地写入也没有必要索取 API 密钥。
3. **推荐：统一内容与交付状态，按平台选择连接器、官方 API/CLI 或导入。** 有可写宿主连接器时复用连接，不重复索取密钥；没有连接器时走已核实的官方接口；只能网页导入时如实说明交互和调度限制。Markdown/DOCX 也是可独立交付的输出。

## 用户交互

在新课程开始时，先复用请求、现有课程和已连接工具中的信息。仅在缺项时分轮沟通：

1. 询问目标平台和位置，可选择 PDF、本地 Markdown/DOCX 或云文档；可附加 PDF 副本，但默认不强制生成 PDF。
2. 根据平台询问最少必要信息：父页面/文件夹/知识库链接，Obsidian Vault 路径，已有连接器，或凭据所在的环境变量/本地私有文件。只询问所选平台，不罗列其他平台的密钥要求。
3. 只在授权不足、目标不明确或验证失败时再追问，解释具体缺项和可行替代路线。用户拒绝配置云端时，提供其确认过的文件输出方式；不静默降级。

凭据通过现有宿主授权、环境变量或仓库外私有文件使用。课程配置只保存凭据引用、目标标识和交付模式；不在对话中要求粘贴 Secret，不把凭据写入课程、日志、示例或安装 ZIP。

展示计划文档与课程安排，仍需学习者明确批准当前计划，之后才启动正式每日任务。已批准的计划、输出位置和授权范围在后续执行中复用；新目标、失效凭据或必要变更才重新沟通。网页登录或手动导入无法稳定无人值守时，在创建调度前说明限制。

## 平台接入设计

| 平台 | 首选路线 | 最少信息与验证 |
| --- | --- | --- |
| Notion | 宿主可写连接器，或官方 Markdown 页面 API | 已授权父页面、令牌引用；创建课程首页与计划/每日子页面，读取返回页面和内容验证 |
| Obsidian | 在明确指定的本地 Vault 课程子目录写 Markdown 和资源 | Vault 路径与课程目录；不要求账户或 API key；校验文件和图片引用，返回笔记路径/打开链接；同步状态由用户现有同步软件管理 |
| 飞书 | 可写连接器，或官方上传素材→导入任务→查询结果流程 | 应用/用户授权与目标文件夹；持久化任务标识，检查导入完成并核对文档内容 |
| 腾讯文档 | 可写连接器，或官方文件导入 API | Client ID、Open ID、Access Token 的私有引用与目标文件夹；开发时进一步核对预导入、上传、异步导入和查询结果的官方参数 |
| 钉钉 | 可写连接器，或官方 dws 文档导入 CLI | 已登录/获授权 CLI 和目标文件夹/知识库；核对 nodeId/documentUrl 与可编辑文档类型，读取验证 |

没有直接接入条件时，可用宿主浏览器/桌面工具在用户授权目标内导入，返回实际文档链接并核对内容；缺少 UI 工具或登录时交付导入文件并标注待导入，课程云端交付不能标记完成。网页路线需要当前 UI 观察，不能在 Skill 内固化脆弱坐标或使用浏览器私有认证接口。

## 实现结构

保留自包含 `skills/omni-learning-anything/` 安装结构。在 `SKILL.md` 放平台选择与交付流程；复杂接入、设置和恢复细节分配到按需读取的 references。新增确定性脚本处理文档导出、平台预检、直接接入、回执和重试恢复；宿主连接器/网页操作由 Agent 调用真实工具，并记录工具返回证据。

把与格式无关的内容校验从 PDF 模块抽离：学习时间、连续课程、至少五个扩展链接、引用、图片与版权说明在所有输出中一致。Markdown/DOCX/云文档生成不导入 PDF 库、不要求 XeLaTeX。仅 PDF 路径保留真实编译、字体与逐页预览检查；DOCX 和云文档按其实际渲染验证标题、正文、图片、链接和中文显示。图片必须复制到 Vault/导入包或通过平台支持的上传流程写入；不能在远端页面保留失效的本地路径。

配置增加明确的目标平台、传输模式、输出格式、目标位置和凭据引用。旧版没有这些字段的课程继续按 PDF 工作；历史示例及批准哈希不因升级而被改写。已有课程变更输出位置时提供显式迁移/新版本流程，重新确认相关设置，保留旧交付档案。

文档 manifest 使用统一的 artifact 字段，同时兼容旧 `pdf` 字段。课程状态分别记录本地生成、审核、目标上传/导入中、验证成功、交付完成和待核对。文档回执与审核 manifest 分离，避免上传状态变化破坏已审核内容哈希。只有所选主要交付目标验证成功，才允许记录该课已交付并推进学习日。

每份计划/课程与目标使用稳定交付标识。保存云端文档 ID、导入任务 ID、内容哈希和链接，恢复时优先复用；请求超时而服务器可能已写入时标为待核对，不盲目再次创建。可查询的异步任务从已保存任务标识继续；不能证明成功或失败时等待核对，不承诺跨平台严格 exactly-once。多个副本部分失败时记录各自状态，主要交付目标成功才推进，重试不得重复创建已成功副本。

## 验收

- 回归原有课程状态、批准、暂停、每日限制、不可变档案和 PDF 编译测试。
- 在无 XeLaTeX 环境完成 Markdown、DOCX、Obsidian 输出；检查中文、引用、图片、练习和扩展链接。
- 对每个平台验证配置缺失、权限不足、异步等待、失败、请求结果不明、重试复用和成功回执；使用契约模拟验证不可重复创建和不可错误推进。
- 用独立测试课程验证真实学习流程，不为样例创建正式每日调度。
- 本机真实账号联调只创建有明确名称的 v2 QA 文档和课程目录，保留验收链接；账户需要登录、扫码或授权时请用户完成对应交互。不会把已有登录状态直接视为所有 API 已授权。
- 报告每个平台的实际路径、结果、文档链接、日期和未验证原因；本地模拟通过不能写为真实账号通过。
- 完成后更新 Skill metadata、界面文案、README、CHANGELOG、接入说明，重新生成 `omni-learning-anything-skill-v2.0.0.zip` 与 SHA256SUMS，检查安装包包含必要资源且不含凭据或课程数据。
- GitHub 正式 Release 属于后续发布动作；先交付可审核代码、测试记录和 v2.0.0 安装包，是否发布按用户后续明确指令执行。

## 设计自检

本版覆盖五个指定平台且保留 PDF；所有新格式使用相同学习内容约束。授权与凭据按平台最小收集，未明确选择时询问，缺信息不伪造交付。云端验证失败不能推进课程；超时不盲目重复创建。旧课程保持兼容，图片、真实账号验证和版本安装包均纳入验收。通用文件兼容不等同未测试平台的原生支持。待用户确认后编写实施计划并开始开发。
