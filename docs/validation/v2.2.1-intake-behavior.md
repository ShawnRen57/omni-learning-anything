# v2.2.1 intake behavior observations

Date: 2026-10-31. Method: one independent reviewing agent read the actual updated Skill and its applicable references, then responded to three isolated learner requests. This is a model-based instruction-following check, not an external learner study or a controlled comparison with v2.2.0. No course approval, cloud write, real schedule or learning result was produced.

## 1. Broad request, limited appetite for questions

Request: “我想学点经济学，别给我一堆问题。”

Observed first reply proposed daily choices/prices/incentives as an editable direction, with a route through opportunity cost, supply/demand, incentives/market failure, introductory macro concepts and a synthesis case. It excluded econometric derivations and investment operations. The assumed non-calculus approach, 30 days and 10–15 minutes remained proposals, not confirmed baseline or settings. It asked only where to save materials in this first exchange.

Outcome: a vague request received a meaningful bounded starting route and explicit assumptions, without a long questionnaire. The course still needed research, remaining settings and user review; this reply did not imply completion or approval.

## 2. Concise but specific request

Request: “SQL JOIN，三天后面试，每天20分钟，中文，Markdown存本地，我是刚入门。”

Observed route:

- Day 1: necessary SELECT/FROM and join keys, INNER JOIN, write a query and explain result rows.
- Day 2: LEFT JOIN, unmatched rows and ON/WHERE distinctions, preserve left-side rows and find a faulty query.
- Day 3: one-to-many row counts, mixed timed exercises and spoken query explanation.

It preserved the supplied language, duration, beginner baseline, format and 20-minute budget, splitting time into examples/practice/review. It requested the missing local folder and course timezone, proposing the environment's Asia/Shanghai for confirmation. It did not add a live schedule or broaden the course to all database topics.

Outcome: brevity did not trigger an unnecessary clarification questionnaire. The route remained provisional pending real source research and plan review.

## 3. Meaning and intended use still ambiguous

Request: “我想学Agent。”

Observed first reply asked which direction the learner meant: understand/use AI agents, build AI agents, or an Agent in another field. It explained that the answer affects content and prerequisites, without assuming a programming baseline or generating a whole curriculum first.

Outcome: a question was reserved for ambiguity that substantially changes the course. In a real conversation, existing context could already resolve this ambiguity and should be reused.

## Limits and future evaluation

These observations show possible behavior under the updated instructions. They do not prove consistent behavior across all host models, richer final teaching materials or improved learning outcomes. Keep evaluating actual plans for scope fit, prerequisite order, outcome alignment, worked examples, source support and realistic workload. No production quiz/grading/adaptive-learning engine is added in v2.2.1.
