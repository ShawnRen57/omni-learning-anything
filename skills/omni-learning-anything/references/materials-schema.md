# Material commands and evidence contract

`OMNI` resolves to the installed `python .../scripts/omni_learning.py --project /absolute/course`. The agent runs commands, manages staging files and explains results. Private snapshots live under course/materials, not in the installed bundle.

```sh
OMNI materials import --file /user/provided/book.pdf
# Host first obtains actual accessible website content; this command does not fetch URLs:
OMNI materials import --file /private/page.html --url https://publisher.example/article
OMNI materials list
OMNI materials inspect --id ACTUAL_MATERIAL_ID --version ACTUAL_VERSION
OMNI materials select --id ACTUAL_MATERIAL_ID --version ACTUAL_VERSION --pages 20-35
OMNI materials select --id ACTUAL_MATERIAL_ID --version ACTUAL_VERSION --heading 'Chapter title'
OMNI materials select --id ACTUAL_MATERIAL_ID --version ACTUAL_VERSION --unit u000001 --unit u000002 --exclude-unit u000002
OMNI materials search --selection /private/selected-range.json --query 'specific concept' --limit 5
OMNI materials cite --selection /private/selected-range.json --unit ACTUAL_UNIT --quote-file /private/actual-excerpt.txt --source-id S1 --checked-at ACTUAL_COURSE_DATE
```

The import result includes actual ID/version/title/kind/status/warnings/unit count. Preserve them; never invent IDs, page locations or quotes. Outline units include IDs/locators/headings/page metadata. `--pages` uses original PDF indices only; non-PDF inputs must use headings/unit IDs. An absent/ambiguous heading fails with guidance to inspect candidates. A selected range includes all its chunks unless explicitly excluded. Search returns only matching selected units, with actual text, locator, version and selection hash, bounded to limit (1–10). No result is a legitimate outcome; do not search unrelated course material to fill it.

A selection is returned as `{id,version,snapshot_hash,units,hash}`. Keep the complete returned value; hashes are generated by helpers. Put it in `config.json`:

```json
{"materials":{"policy":"strict","selections":["REPLACE WITH THE ACTUAL RETURNED SELECTION OBJECT"]}}
```

That illustrative string is not valid configuration. Each actual selection must contain the returned material ID, raw-byte version, snapshot integrity hash, unit ID list and hash. `init` validates the selection against local snapshots before accepting a new course. Without `--selection`, search uses current config selections. Once config exists, an explicitly supplied selection must match one of its ranges. Supplying a different range is not permission to alter an approved course.

`materials cite` returns an ordinary S-number source with title/publisher/publication date/check date/note and:

```json
{"material_ref":{"id":"ACTUAL_ID","version":"ACTUAL_VERSION","selection_hash":"ACTUAL_SELECTION_HASH","unit":"ACTUAL_UNIT","quote":"ACTUAL_SUBSTRING"}}
```

Quote must occur in the selected unit; the visible source note must include that unit's original locator. `url` is absent for private local files, or equals the captured public website origin. Do not invent `file://` or fake HTTP links. Document exporters preserve these sources as plain text when no public URL exists. Each claim/quiz explanation still uses matching `[S1]` etc in the authored text.

Retries: `materials import --file FILE --id EXISTING_ID --retry` retries only failed/unavailable extraction. Existing ready/partial snapshots remain immutable; a modified/OCR-corrected source creates a new byte version. Different public-origin metadata cannot silently replace a ready version. No reset/update command changes selected approved snapshots. Registry hashes check integrity, not extraction truth, copyright permission or semantic entailment.
